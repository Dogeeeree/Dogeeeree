## How I Like To Build

I prefer useful over fancy.

My usual process is:

1. Understand the real problem.
2. Test the risky part first.
3. Make the setup repeatable.
4. Write it down so the next person can do it without guessing.

I care a lot about clear instructions, because a good tool is not really finished until someone else can run it without fear.

## Working Style

I learn by building. I like direct feedback, fast iteration, and practical results. If something is confusing, I would rather make a checklist, script, or visual explanation than leave it as "tribal knowledge."
